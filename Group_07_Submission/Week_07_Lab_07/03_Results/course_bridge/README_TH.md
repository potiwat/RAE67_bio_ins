**วิธีนับ** เวลาตอบสนองของหนึ่งอินพุตเท่ากับเวลาที่ช้ากว่าระหว่างการเปลี่ยนคำสั่งเคลื่อนไหวครั้งแรกกับการเปลี่ยนคำสั่งสีครั้งแรก ลบเวลาต้นกำเนิดอินพุต จับคู่ตาม ID และชนิดเหตุการณ์ภายในหน้าต่าง 0–22 s เมื่อพบทั้งสองภายใน ≤1.00 s ให้นับว่าผ่าน เมื่อพบครบแต่เกิน 1.00 s ให้นับว่าเลยกำหนด เมื่อขาดอย่างน้อยหนึ่ง onset ให้เก็บ N/A ตารางดิบแยกจำนวนที่สังเกตครบออกจากจำนวนที่คาดไว้

จำนวนข้อความที่ส่งเท่ากับจำนวนที่รับรวมจำนวนที่ถูกทิ้งระหว่างส่งและจำนวนที่ยังเดินทางเมื่อจบรอบ จำนวนที่รับเท่ากับจำนวนที่รับเข้าใช้บวกจำนวนที่อ่านแล้วทิ้งเพราะ sequence เก่ากว่าค่าล่าสุด อายุข้อความคำนวณด้วยเวลารับลบเวลาส่ง เฉพาะข้อความที่รับก่อนจบรอบ

**แหล่งที่มาของ fault** ทุกเงื่อนไขจงใจป้อนค่าระยะผิดปกติช่วง 11.00 ถึงก่อน 11.14 s และป้อนตัวอย่าง touch เก่าช่วง 12.00 ถึงก่อน 12.26 s เงื่อนไข ideal แต่ละรอบจึงมี 7 และ 13 fault ticks ในสองช่วงดังกล่าวตามลำดับ และศูนย์นอกสองช่วง เมื่อใช้ stressed พบ 39, 65 และ 39 fault ticks นอกสองช่วงเดิมตามลำดับ seed การแบ่งนี้ยึดเวลาของ tick หลังรับข้อความ ข้อความจากช่วงทดสอบที่มาช้าจึงอาจมีผลต่อ tick ภายหลังได้

## ขอบเขตและหลักฐาน

เจ็ด application topics ประกอบด้วย button/touch แบบ Bool, distance แบบ Float32 หน่วย m, interaction และ emotion แบบ String, servo_command แบบ Float32MultiArray หน่วย rad ตามลำดับ [tilt, extend, nod] และ rgb_command แบบ ColorRGBA ค่า RGB หาร 255 และ alpha = 1 สัญญา ROS กำหนด RELIABLE, KEEP_LAST depth 10, VOLATILE ตัวอย่างคำสั่งในไฟล์จริงของการจำลอง C0/41 ที่ 1.14 s เป็น interested ให้ [0.016, 0.016, 0.016] rad และ [1.0, 0.70588235, 0.0, 1.0] [สัญญาเจ็ด topic](runtime/interface_contract.json) · [คำสั่งที่บันทึกของ C0/41](runs_20261112/C0_r01/command_trace.csv)

การทดลองนี้ใช้ process เดียวและนาฬิกาเสมือนร่วมกัน ค่า latency สิ้นสุดที่การเปลี่ยนคำสั่งจำลอง การวัด ROS/DDS บนเครือข่ายและการวัดมุมหรือแสงจากโคม Raspberry Pi 5 ต้องใช้บันทึกคนละชนิด ข้อความของทั้งเจ็ด topic ไม่มี Header เชื่อม ID และเวลา acquisition กับผู้รับ การอนุมานเวลา source-to-physical ต้องมีการเชื่อมเวลาและการวัด onset ที่ตัวอุปกรณ์

## ตรวจหรือรันใหม่

เปิดเทอร์มินัลใน `03_Results/course_bridge` ใช้ Python 3.10 ขึ้นไป ตัวรันใช้เฉพาะ standard library ตรวจชุดผลที่จัดส่งด้วยคำสั่งนี้

```text
python -B verify_results.py
```

หากจะทำการทดลองใหม่ ให้เลือกชื่อโฟลเดอร์ผลลัพธ์ที่ยังว่างสำหรับทั้งการรันหลักและ replay ตัวอย่างต่อไปนี้ใช้ `new_runs` และ `new_replay`

```text
python -B runtime/check_submission.py --policy-file runtime/completed_policy.py --contract group
python -B runtime/offline_lab.py --policy-file runtime/completed_policy.py --condition all --repeats 3 --output-dir new_runs
python -B runtime/offline_lab.py --policy-file runtime/completed_policy.py --condition C1 --repeats 1 --replay new_runs/C1_r02/input_trace.csv --output-dir new_replay
```
