# ปัญหาที่พบและวิธีแก้ไข

บันทึกปัญหาที่เจอระหว่างสร้างและทดสอบ Lamp_Robot (6–12 พ.ย. 2026) เรียงตามลำดับที่พบ
สถานะ: **แก้แล้ว** / **ยังเปิดอยู่** / **ป้องกันไว้ก่อน** (ยังไม่เกิดจริง)

## ช่วงที่ 1: ประกอบหุ่นและทดสอบมอเตอร์ (6–7 พ.ย.)

| # | อาการ | สาเหตุ | วิธีแก้ / วิธีป้องกัน |
|---|---|---|---|
| 1 | VS Code ขีดเส้นแดงใต้ `#include <ESP32Servo.h>` | IntelliSense ใช้ env อื่นที่ไม่มีไลบรารีนี้ | เลือก env ให้ถูกในแถบ PlatformIO แล้ว reload หน้าต่าง (build จริงไม่มีปัญหา) |
| 2 | MG996R บน ESP32 ขยับไม่นุ่มเท่าบน Arduino UNO | ESP32Servo ตั้ง PWM 10 บิตเป็นค่าเริ่มต้น (~19.5 µs ต่อขั้น มากกว่า 1°) | เรียก `setTimerWidth(16)` **หลัง** `attach()` เพราะ attach รีเซ็ตค่านี้ |
| 3 | อัปโหลดไม่ได้ "port is busy" | Serial Monitor ยังเปิดอยู่ | ปิดโปรแกรมที่เปิดพอร์ตก่อนอัปโหลดทุกครั้ง (ตอนนี้คือ runLAMP) |

| 6 | พิมพ์ใน monitor แล้วไม่เห็นตัวอักษร | monitor ของ PlatformIO ไม่ echo | ตั้ง `monitor_echo = yes`, `send_on_enter`, `monitor_eol = LF` |
| 7 | คำสั่งที่มีเว้นวรรคถูกปฏิเสธ, `m 180` อ่านเป็น 18 | แป้นพิมพ์ภาษาไทย ปุ่มลูกศร และ backspace ส่งไบต์แปลก ๆ มา | ตัวอ่านคำสั่งข้ามรหัส ESC และรองรับ backspace / พิมพ์ด้วยแป้นภาษาอังกฤษ |
| 8 | **servo STS พัง 2 ตัว** (ID 3, 4) หลังสั่ง `mid` / `sweep` | ตำแหน่ง STS วน 4095 → 0 ช่วงที่สอนไว้ข้ามจุดนี้ ค่า min/max จึงหมายถึงฝั่งที่ผิด servo หมุนทะลุฝั่งที่ติดขัดด้วยแรงเต็ม | `teach` ตั้ง origin เป็น 2048 ก่อน ตรวจจับการข้ามจุด และไม่ยอมบันทึกช่วงที่ไม่ปลอดภัย หดขอบเข้า 1.8° จำกัดแรงบิด 50% (จำลอง 20,000 กรณี ไม่ชนเลย) |
| 9 | origin เท่ากับหรือเลย min ไปนิดหน่อย | ตอนสอน origin ดันข้อไว้ชนขอบ | origin ต้องอยู่ในช่วง และหดขอบเข้าไป ไม่ให้ชนขอบตอนกลับ origin |
| 10 | MG996R ไม่ขยับทั้งที่ส่งสัญญาณถูก | ไฟเลี้ยงไม่พอ (ใช้ไฟจากบอร์ด) | ตรวจสัญญาณด้วย `mdiag` และมัลติมิเตอร์ **แก้โดยให้ MG ใช้แหล่งจ่ายแยก** |
| 11 | ESP32 รีเซ็ต (`POWERON_RESET`) ทันทีที่ MG ขยับ | MG ดึงกระแสจน 5 V ของบอร์ดตก | แหล่งจ่าย MG แยก (5–6 V ≥ 2 A) GND ร่วม ใส่ตัวเก็บประจุ 470–1000 µF ได้ |
| 12 | ตัวอักษรใน Serial หายตอน MG ทำงาน | สัญญาณรบกวนจาก MG บนไฟ 5 V ของบอร์ด | แก้แบบเดียวกับข้อ 11 |
| 13 | MG หลุดเป็นช่วง ๆ / `ID 4: no reply` | สาย Dupont หรือขั้วต่อบัสถูกดึงตอนข้อต่อขยับ | รัดสายใกล้ข้อต่อ เผื่อความยาวให้หมุนได้สุด ติดกาว/เทปที่ขั้วต่อ |
| 14 | ESP32 ค้าง `Interrupt wdt timeout on CPU1` ตอนสั่ง `m on` | ค้างใน `Servo::attach` เมื่อ attach ซ้ำหลัง detach (ESP32Servo 3.2.1 + core 3) | โปรแกรมหลัก attach MG **ครั้งเดียว** ตอนบูต ไม่ detach เลย จะปล่อยแรงใช้ `ledcWrite(pin, 0)` หยุดสัญญาณแทน |
| 15 | MG กระโดดตอนเปิดไฟ | MG996R ไม่มีตัววัดตำแหน่ง | ไม่วางของใกล้ฐาน ตอนบูตให้ไปที่ origin ทันที |
| 16 | MG ตัวเลียนแบบหมุนมั่ว (สงสัย) | MG996R บางรุ่นเป็นแบบหมุนต่อเนื่อง 360° | ทดสอบ: ที่ 90° ต้องค้างตำแหน่ง ไม่ใช่หยุดหมุน |
| 17 | torque limit กลับเป็น 100% หลังไฟ servo กระพริบ | ค่านี้อยู่ใน RAM ของ servo ตั้งแค่ตอน ESP32 บูต | โปรแกรมหลักเขียน torque limit ซ้ำทุก 5 วินาที |
| 18 | คำสั่ง `p` / `a` ข้ามการล็อก "ต้อง teach ก่อน" | ทางลัดในโปรแกรมทดสอบ | ไม่ใช้หลัง `lim reset` / โปรแกรมหลัก clamp ทุกคำสั่งให้อยู่ในช่วง |
| 19 | เปิดพอร์ตแล้ว ESP32 รีเซ็ต | สาย DTR/RTS ของชิป USB ต่อกับวงจรรีเซ็ต | เป็นเรื่องปกติ โปรแกรมหลักต้องกลับมาทำงานเองได้หลังรีเซ็ต |
| 20 | ศอก ID 2 ยกขึ้นเหนือ origin ได้แค่ +2.3° | สอน origin ไว้ที่ปลายบนสุด | ให้ท่าของ CPG อยู่ต่ำกว่า origin (เช่น −20°) หรือ teach ใหม่ |
| 21 | ไหล่ ID 1 ร้อน 67–69 °C หลังทำงานไม่กี่นาที | ไหล่รับน้ำหนักทั้งแขนและหัว และการหายใจทำให้ไม่ได้พักเลย STS ตัดเองที่ ~70 °C | จังหวะ CPG ค่อย ๆ หายที่ 55–62 °C, ปิดแรงที่ 66 °C, เปิดคืนที่ 55 °C และเพิ่มฮอร์โมน fatigue ให้หุ่นงีบก่อนร้อนเกิน |

| 53 | ของหายจากฐานแล้วหุ่นตกใจทุกครั้ง (6 จาก 6) | หัวยังก้มอยู่ ToF หัววัดโต๊ะ/มือได้ ~25 cm | ตอน interested / bored ที่ของหายไป และ 3 s หลังเลิกก้ม ไม่ใช้ ToF หัว |
| 54 | ความเบื่อไม่สะสม novelty พุ่งซ้ำ | กล้องเห็นของบ้างไม่เห็นบ้าง id ของสลับ 9 → 0 → 9 นับเป็นของใหม่ทุกครั้ง | ของยังอยู่ที่ฐาน = ชิ้นเดิม กล้องหลุดใช้ id เดิม |
| 55 | ยกของให้ดู หัวเงยตามไม่ได้ | ของกระโดด = ถูกยก รอ 1 s และแขนล็อกท่าก้ม | ผู้ใช้เลือก: ตามของ **ซ้าย-ขวาอย่างเดียว** ไม่เงย/ก้มตามของ รอ 0.4 s |
| 56 | **(ยังเปิดอยู่)** ลงมาดูของก็เบื่อเลย ความเบื่อสะสมก่อนก้ม | ฮอร์โมนเบื่อนับแค่ "มีของที่ฐาน" ไม่ดูอารมณ์ ตอนกดปุ่ม sleepy ค้างไว้แล้ววางของ ความเบื่อขึ้นถึง 0.35–0.56 และของที่กล้องไม่รู้จักใช้ความจำ id 0 ร่วมกัน | เสนอ: ให้สะสมเฉพาะตอน interested / bored (รอผู้ใช้เลือกวิธี) |
