## พฤติกรรมปัจจุบัน (ค่าตั้งใน behavior.BrainConfig / sensor_perception.SensorPerceptConfig)
- ตรวจจับ <= 70 ซม. (ปล่อย 85) ; สนใจ: อยู่ในระยะ 2 วิ + curiosity >= 15% (ลดตามความป่วย x(1-1.6 ป่วย))
- อบอุ่น: affinity > 28% + สนใจมาแล้ว 4 วิ ; เต้น 4 วิ ; อยู่นิ่งนาน 30 วิ "อิ่ม" -> กลับสนใจ
- กลัว: reflex S >= 0.65 หรือ H caution >= 0.40 ; เข้ามาเร็ว 0.4-0.9 ม./วิ อะดรีนาลีนขึ้นตามความเร็ว ค้าง 3 วิ ;
  ตบ/ผลัก/ดุ ; ประชิด < 20 ซม. ที่ "เข้ามา" จริง
- ป่วย: >= 45% = สถานะ Sick มาก่อนอารมณ์อื่น (< 25% หาย) ; หัวห้อย หนาวสั่น ไฟซีด ; ง่วงง่าย ; นอนนานขึ้นสูงสุด 16 นาที ;
  ปุ่ม 4 รักษา / 1 ลูบหัว เร่งหาย
- หลับ: ไม่มีใคร ~40 วิ หรือตื่นครบ 12 ชม. (หลับแม้มีคน) ; หลับตา (รับแค่ปุ่ม 5) ; แอบดูทุก 20 วิ ; นอน 8 นาทีแล้วตื่นเอง
- มองตาม: จ้องนิ่ง ; หลุดหาใกล้ๆ (+-10/25/45) แล้วกวาด +-85 ; ล็อกระยะเป้า (แยกมือจากตัวคน 5 ซม.) ;
  คอเอียงนำแล้วฐานหมุนตาม ; ไฟวิ่งวน
- กลไกชีววิทยา: habituation, efference copy, looming, ความคุ้นเคยสถานที่ (background map), active sensing,
  sentinel peek, sleep pressure, sickness behavior

## 1. โปรเจกต์นี้คืออะไร

โคมไฟแขนกล 5 DOF สไตล์ Luxo Jr. ที่ตอบสนองคนที่เดินผ่านหรือเข้าใกล้
อารมณ์ไม่ได้มาจาก if-else แต่มาจาก **ระบบฮอร์โมนเทียม (AHM)** ตามไฟล์
`hormone-robot-design-notes.md` ที่ผู้ใช้ส่งมาตอนเริ่มโปรเจกต์
(ไฟล์นั้นเขียนไว้สำหรับหุ่นเดินหกขา เราพอร์ตสถาปัตยกรรมมาใช้กับโคม)

### ฮอร์โมน 4 ตัว

| ฮอร์โมน | สิ่งเร้า | ผลต่อโคม | ครึ่งชีวิต |
|---|---|---|---|
| caution | คนพุ่งเข้าหา / ใกล้เกินไป / คนหลายคน | หดตัว ถอยหลัง ขยับช้าลง | 4 วิ |
| curiosity | คนระยะกลาง เคลื่อนไหวช้า มีความใหม่ | โน้มเข้าหา ตามมองไวขึ้น | 10 วิ |
| affinity | คนอยู่ใกล้อย่างสงบต่อเนื่อง | แสงอุ่นขึ้น โยกเบาๆ | 40 วิ |
| sleepiness | ไม่มีคนนาน / แสงมืด | ห้อยหัว แสงหรี่ | 25 วิ |

FSM 6 สถานะ: Idle, Curious, Engage, Shy, Sleep, Blind (+ Protect ฝั่งบอร์ด)

## 2. สถาปัตยกรรม

```
โน้ตบุ๊ก (Python)                    ESP32 (MicroPython)
กล้อง -> perception -> ฮอร์โมน       <- UDP/WiFi ->   CPG -> ท่าทาง -> safety -> เซอร์โว
      -> FSM -> พารามิเตอร์                            telemetry กลับ
```

**โน้ตบุ๊กคิดว่า "ควรรู้สึกยังไง" ส่วน ESP32 ตัดสินว่า "ขยับได้แค่ไหน"**
โน้ตบุ๊กส่งได้แค่พารามิเตอร์ (tempo, amp, lean, gaze_follow, brightness, warmth)
กับโหมดและทิศมอง ห้ามสั่งมุมข้อต่อตรงๆ

## 3. ฮาร์ดแวร์จริง

- ESP32 DevKit บน expansion board สีม่วง, พอร์ต **COM5**
- Waveshare Bus Servo Adapter (A) จัมเปอร์ฝั่ง **A (UART)**, `PIN_DIR = None`
- สาย: adapter TX -> ESP32 **G16**, RX -> **G17**, GND ร่วม
- เซอร์โว Feetech **SCS15** 5 ตัว บัส 1 Mbps, big-endian
- ไฟเลี้ยงเซอร์โว 7-7.8V แยกจาก ESP32 กราวด์ร่วม
- กล้อง USB ติดบนหัวโคม

## 4. สถานะปัจจุบัน (ทำถึงไหนแล้ว)

### ทำงานได้แล้ว
- ลิงก์ WiFi UDP สองทาง (บอร์ดเป็น AP ชื่อ `lamp-robot` รหัส `lamp12345`, ยิงไป 192.168.4.1:9000)
- สมองฝั่งโน้ตบุ๊กครบ: กล้อง, ฮอร์โมน, FSM, โคมจำลองบนจอ
- บอร์ดรับคำสั่งและส่ง telemetry กลับได้ สถานะตรงกันทั้งสองฝั่ง
  (ยืนยันแล้ว: Idle -> Curious -> Engage -> Shy ไล่ตามกัน)
- คาลิเบรตด้วยมือไปแล้วบางส่วน ท่า Curious ออกมาสวย (มีรูปยืนยัน)

### คาลิเบรตแล้ว (calib.py บนบอร์ด, 4 ข้อต่อ ข้าม head_roll)
| ข้อต่อ | id | center | invert | soft | ท่า 0 / ทาง + |
|---|---|---|---|---|---|
| yaw | 4 | 505 | True | -90..90 (cap) | หันตรงหน้า / หันซ้ายของโคม |
| shoulder | 9 | 510 | False | -60..30 (cap, กลไก -111..118; หน้า 52 แล้วตกค้าง load 1000 ไฟบัสตก 4.5V) | แขนล่างตั้งตรง / เอนหน้า |
| elbow | 7 | 520 | True | -35..65 (cap) | แขนบนตรงต่อแขนล่าง / พับหน้า |
| head_pitch | 2 | 495 | False | -56..87 (กลไก -5 องศา) | หัวแนวเดียวกับแขนบน / ก้มลง |

config.py (ค่าสำรอง) และ LIMITS ใน lamp.py ตั้งตรงกับตารางนี้แล้ว
**head_roll ถูกใส่ # ปิดไว้ใน config.py** (บอร์ดใหม่ไม่มี calib.py จึงใช้ config.py ตรงๆ) ซิมยังมีครบ 5 ข้อต่อ เทสกันไม่ให้เปิดในบอร์ด
บอร์ดปัจจุบัน: ESP32 ตัวแรกสุด (CP210x, COM5, MicroPython 1.29) ล้างด้วย `wipe_board.py` แล้วลงใหม่ทั้งชุด
center ใหม่ต่างจากค่าเก่า (เก่าไม่รู้ที่มา) -> **ท่าต่างๆ บนหุ่นจริงอาจดูต่างจากเดิม ต้องดูด้วยตาแล้วจูน**

### เปลี่ยนทิศ: เลิกใช้กล้อง (ไม่ตรงกับแล็บของอาจารย์ repo potiwat/RAE67_bio_ins)
เซนเซอร์ใหม่ต่อตรงที่ ESP32 (ตกลงกับผู้ใช้แล้ว):
| เซนเซอร์ | ขา | ใช้ทำอะไร | สถานะ |
|---|---|---|---|
| ความชื้นดิน (แผ่นแดง) สายลอย จุ่มแก้วน้ำ (คาลิเบรตแล้ว: อากาศ raw 0, จุ่มน้ำ ~20000, จับมือ ~0.5) | AO->34, VCC->25 (เปิดเฉพาะตอนอ่าน) | จุ่มน้ำ = ป่วย -> ฮอร์โมน sickness | โค้ดเสร็จ `moisture.py` + `tools/sense.py` ยังไม่ต่อเข้าลิงก์ |
| อัลตร้าโซนิค HC-SR04 | VCC->หมุดแดง (3.3V), Trig->26, Echo->27 ต่อตรง | ระยะสนใจ 0.2-1.2 m ยิ่งใกล้ curiosity ยิ่งขึ้น, ใกล้เกิน caution, ไกล sleepiness | โค้ดเสร็จ `ultrasonic.py` (median3 + low-pass, stale 0.5 s -> None) ยังไม่ต่อเข้าลิงก์ |
| keypad 4x3 (แทนสัมผัส) | สายแพ 7 เส้น -> 18,19,21,23,32,33,14 (หมุดเหลือง) | 1 ลูบหัว(care,affinity++) 2 ลูบแขน(affinity+) 3 ทักทาย(curiosity) / 4 สะกิด 5 ปลุก 6 กล่อมนอน / 7 ตบหัว(สะดุ้ง caution++) 8 ผลัก 9 ดุ(caution, affinity-) ; * 0 # ยังว่าง | โค้ดเสร็จ `keypad.py` สแกนคู่ขา (ต่อสายลำดับไหนก็ได้) + `tools/keys.py` เรียนรู้ลำดับขา ยังไม่ต่อเข้าลิงก์ |
LDR ยกเลิกแล้ว (ผู้ใช้เปลี่ยนเป็นเซนเซอร์ความชื้น)
expansion board สีม่วง: แต่ละขามีหมุด ดำ=GND แดง=V เหลือง=สัญญาณ ; **จัมเปอร์ JUMP เชื่อม V-3V3 -> หมุดแดงทั้งหมด = 3.3V**
5V เอาจากหมุดเหลืองคอลัมน์ `5V` ; ถ้าย้ายจัมเปอร์ไป 5V ต้องลดแรงดัน Echo และห้ามเสียบเซนเซอร์ความชื้นที่หมุดแดง
**ทดสอบทุกอย่างทีเดียว: `import tools.all`** (ไฟวงแหวนตอบสนองสด + สรุปค่าคาลิเบรต) ; แยกทีละอย่าง: `tools.sense`, `tools.keys` (เรียนรู้ลำดับขา), `tools.ring` (ไม่ขยับเซอร์โว)
ไฟโคม = วงแหวน NeoPixel (DI->P5, VCC->แดง 3.3V, GND) `LED_TYPE="neopixel"`, `LED_COUNT` (นับด้วย `import tools.ring`), เพดาน `LED_MAX=0.3` เพราะตัวจ่าย 3.3V บนบอร์ดรับกระแสวงแหวนเต็มที่ไม่ไหว

ฮอร์โมนตัวที่ 5 **sickness** (ahm.py): ป่วยเร็ว (~10 วิถึงครึ่ง) หายช้า (ครึ่งชีวิต 90 วิ)
สิ่งเร้า `care` (ลูบหัว) เร่งให้หาย (ครึ่งชีวิต 15 วิ) ; ผลอยู่ใน `Modulator.resolve`:
curiosity x(1-0.7k), sleepiness +0.5k, caution x(1+0.5k) และลด tempo/amp/lean/gaze/brightness/warmth
### เชื่อมเซนเซอร์เข้าสมองแล้ว (สมองยังอยู่บนโน้ตบุ๊ก -- ผู้ใช้เลือก)
```
บอร์ด: sensors.py (อัลตร้าโซนิคแบบ interrupt ไม่บล็อกลูป + ความชื้น + keypad)
  -> telemetry เพิ่ม dist_mm / wet_pct / key / key_seq (link.py ทั้งสองฝั่ง ไฟล์เดียวกัน มีเทสคุม)
โน้ตบุ๊ก: sensor_bridge.py -> SensorPerception (แทนกล้อง) -> LampBrain(perception=...) -> สั่งโคม + logs/run_*.csv
```
- `python sensor_bridge.py` โคมจริง ; `--sim --dry-run` ไม่ต้องมีบอร์ด ; คีย์บอร์ด 1-9 แทน keypad, r รีเซ็ต, q ออก
- สถานการณ์จำลอง `sensor_sim.py` (100 วิ): เข้ามา -> Curious -> Engage -> ตบ Shy -> จุ่มน้ำป่วย -> ลูบหัวหาย -> พุ่งเข้าหา Shy -> ไม่มีใคร Sleep -> ปลุก
  ล็อกด้วยเทส `test_sensor_story_matches_expected_emotions` ฯลฯ
- ระยะกระโดด (ผนัง -> คนเดินตัดหน้า) ไม่นับเป็น "พุ่งเข้าหา" (`jump_mps` 4 m/s) และพุ่งเข้าหานับเฉพาะในระยะ < 1.2 m
- ไม่มีระยะ/ลิงก์หลุด > 2 วิ -> Blind + ค่าปลอดภัย ; ค่าไม่รู้ = None ไม่ใช่ 0
- **ยังไม่ได้รันกับโคมจริง** -- ขั้นต่อไป

### ความนุ่มนวล (ผู้ใช้: "กระตุกตอนกำลังขยับ")
- สาเหตุที่น่าจะเป็น: ส่ง goal speed เพดานคงที่ทุกรอบ -> เซอร์โวพุ่งไปถึงแล้วหยุดรอ (ขั้นบันได) + ลูปตามไม่ทัน (log 400/400)

## 5. บั๊กที่เคยเจอและแก้แล้ว (อย่าทำซ้ำ)

| อาการ | สาเหตุ | แก้ยังไง |
|---|---|---|
| บอร์ดไม่รับคำสั่งเลย (`host_lost` ตลอด) | `struct` ของ MicroPython ไม่รองรับตัวเลขนำหน้า เช่น `"8h"` | เขียนเป็นตัวอักษรซ้ำ `"h"*8` |
| เหมือนเดิม | MicroPython ลบช่วง bytearray ไม่ได้ (`del buf[:n]`) | `Reader` ใช้ `bytes` แทน |
| สแกนเจอ ID ผี `[1,3,7,11,15,19]` | ไม่ได้เช็คว่า ID ในคำตอบตรงกับตัวที่ถาม | `scs._rx(expect_id=...)` + อ่านต่อจนเจอตัวที่ใช่ |
| `ValueError: REPL UART buffer size is fixed` | UART0 เป็นพอร์ต REPL ตั้ง buffer เองไม่ได้ | ย้ายไป WiFi UDP |
| main.py หยุดเองตอน host ส่งข้อมูล | ไบต์ 0x03 ในเฟรม = Ctrl-C ระหว่างช่วงรอ | ทิ้ง stdin หลังหมดช่วงรอ + ย้ายไป WiFi |
| บูตมาแล้วคำสั่งกระโดดเข้าช่วง | ข้อต่ออยู่นอก soft limit ตอนบูต | ให้ค่อยๆ ไล่เข้าช่วง + goal speed ฝั่งเซอร์โว |
| โน้ตบุ๊กรีสตาร์ทแล้วบอร์ดเมินตลอด | seq กลับไปเริ่มที่ 1 ถูกมองว่าเป็นแพ็กเก็ตเก่า | รับถ้าเงียบเกิน PACKET_STALE_S |
| `goto` รายงานค่าผิด | อ่านค่าก่อนเซอร์โวถึงเป้าหมาย | รอจนนิ่งก่อนอ่าน |
| sweep หยุดตั้งแต่ก้าวแรก | ใช้ peak load ตัดสิน ซึ่งพุ่งตอนออกตัว | ใช้โหลดตอนนิ่งแทน |
| ปุ่ม `t` ในวิซาร์ดดูเหมือนทิศไม่เปลี่ยน | ทดสอบจาก center ไม่ใช่จากตำแหน่งปัจจุบัน | ทดสอบจากตรงที่อยู่ |
| วัดช่วงอัตโนมัติ (`l`) ได้ฝั่งล่างผิด | กลับจุด 0 รอแค่ 1.2 วิ ยังไม่ถึงก็วัดต่อ | `_home()` รอสูงสุด 6 วิ + เตือนถ้าไม่ถึง |
| `l` ได้ช่วงแคบผิดๆ กับ shoulder | แขนหนัก/แรงน้อย ไปไม่ถึงเป้าหรือไหลเลยเป้า | วัดด้วยมือ: `r` แล้วดันสุด กด `m` สองฝั่ง |
| `m`/`c` จดตำแหน่งเก่า | ใช้ค่าที่อ่านก่อน prompt ไม่ใช่ตอนกด | อ่านใหม่ตอนกดปุ่ม |
| import tools.wizard ซ้ำแล้วไม่มีอะไรเกิด | บอร์ดจำว่า import แล้ว | Ctrl-D แล้ว Ctrl-C ก่อน import ทุกครั้ง |

## 6. วิธีใช้งาน

### เปิดโปรเจกต์

```
cd lamp_firmware

mpremote connect COM5 fs cp main.py :main.py
mpremote connect COM5 fs cp tools/__init__.py tools/wizard.py tools/check.py tools/calibrate.py tools/autoscan.py tools/sense.py tools/keys.py tools/ring.py tools/all.py :tools/
```

### คาลิเบรต (ต้องทำทุกข้อต่อในรอบเดียว -- เขียน calib.py ทับทั้งไฟล์)
```
mpremote connect COM5 repl
```
Ctrl-C แล้ว `import tools.wizard`

ปุ่ม: `d/a` ±10 tick, `D/A` ±40, `f/s` ±3, `c` ตั้ง 0 องศา, `t` ทดสอบทิศ,
`i` สลับทิศ, `m` จดขีด (ดันด้วยมือจนสุด), `l` วัดช่วงอัตโนมัติ (ไม่แนะนำ), `r` ปลดแรงบิด, `h` ล็อก, `n` เสร็จ, `k` ข้าม, `q` เลิก
ขั้นต่อข้อ: `r` จัดท่า 0 -> `c` -> `h` -> `t` (y/n) -> `r` ดันสุด `m` สองฝั่ง -> กลับท่า 0 `h` -> `n`
เปิดไฟเซอร์โวก่อน และกด Ctrl-D, Ctrl-C ก่อน import

## 8. กฎที่ยึดมาตลอด (จาก design notes)

1. ข้อมูลเสีย = "ไม่รู้" ไม่ใช่ "ปกติ" (stimulus เป็น None ไม่ใช่ 0)
2. ทุกคำสั่งผ่าน clamp -> slew-rate -> goal speed ฝั่งเซอร์โว
3. ฮอร์โมนส่งได้แค่พารามิเตอร์ ผ่าน Bounded Modulation Interface
4. เหตุการณ์เข้าทาง arbiter ทางเดียว (priority + timestamp + State Guard)
5. ห้ามพังเงียบ ทุก fault ต้องมีรายงาน
6. โน้ตบุ๊กเงียบ 0.5 วิ -> safe default, 3 วิ -> ค่อยๆ ลงท่าพัก
7. โดนจับ/โดนขวาง -> ค้างท่า **ไม่ตัดไฟ** (ตัดแล้วแขนตกใส่มือคน)
8. ฝั่งโน้ตบุ๊กกับฝั่งบอร์ดต้องมี POSES/LIMITS ตรงกัน ไม่งั้นจูนบนซิมแล้วใช้จริงไม่ได้

## 9. วิธีคุยกับผู้ใช้

- ผู้ใช้สื่อสารภาษาไทย ชอบคำตอบสั้น กระชับ เป็นขั้นตอน
- **ให้คำสั่งทีละบรรทัด** เมื่อกำลังไล่แก้ปัญหา ไม่ใช่รวดเดียวหลายบรรทัด
- ผู้ใช้มักสับสนระหว่าง PowerShell กับ REPL ของบอร์ด ให้ย้ำว่าต้องดู prompt
  (`>>>` = REPL, `(.venv) PS ...>` = PowerShell)
- ผู้ใช้มักอยู่ผิดโฟลเดอร์ โครงสร้างคือ `lamp-project\lamp-project\{lamp, lamp_firmware}`
- **ลิมิตการส่งรูปในแชทเดิมหมดแล้ว** ให้ผู้ใช้ก็อปข้อความแทน
  หรือบอกมาเป็นตัวเลขสั้นๆ เช่น "tick 522 deg 0.1 load 0"
- เรื่องความปลอดภัย: เตือนให้มือจับสวิตช์ตัดไฟทุกครั้งที่สั่งขยับ
  และให้ปลดแรงบิดทันทีถ้า load เต็มสเกลหรืออุณหภูมิเกิน 45C
