# Firmware โคมหุ่นยนต์ 5 DOF (MicroPython + ESP32 + Feetech SCS15)

ฝั่ง ESP32 ของระบบ: รับพารามิเตอร์จากโน้ตบุ๊ก แล้วสร้างการเคลื่อนไหวจริงที่ปลอดภัย
โน้ตบุ๊กคิดว่า "ควรรู้สึกยังไง" ส่วน ESP32 ตัดสินว่า "ขยับได้แค่ไหน"
ต่อให้โน้ตบุ๊กค้าง สาย USB หลุด หรือมีคนไปจับแขน ESP32 ต้องเอาตัวรอดเองได้

## ลำดับการเอาขึ้นบอร์ด (อย่าข้าม)

ยกโคมให้ลอยหรือหนุนไว้ ยังไม่ต้องมีคนอยู่ใกล้ และเตรียมสวิตช์ตัดไฟเซอร์โวไว้ในมือ

1. **คัดลอกไฟล์ขึ้นบอร์ด** (เช่น `mpremote cp *.py :` แล้ว `mpremote cp -r tools :`)
2. **`import tools.scan`** ตรวจ 4 อย่าง: เจอเซอร์โวครบ 5 ตัวไหม, endianness ถูกไหม,
   memory table ตรงรุ่นไหม, สายเสถียรแค่ไหน ถ้าข้อไหนไม่ผ่าน **หยุดตรงนี้** อย่าไปต่อ
3. **`import tools.bench`** ดูว่าบอร์ดวิ่งได้กี่ Hz จริง แล้วตั้ง `FAST_HZ` ไม่เกิน ~70% ของค่านั้น
4. **`import tools.calibrate`** หา `center_tick`, `invert`, `soft_min/max`, `load_limit`
   ของแต่ละข้อต่อ แล้วเอาไปแก้ใน `config.py` (ดูวิธีใน docstring ของไฟล์)
5. **`import main; main.run()`** ใช้งานจริง

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `config.py` | ค่าตั้งทั้งหมด แก้ที่นี่ที่เดียว |
| `scs.py` | ไดรเวอร์บัส Feetech SCS (half-duplex, sync write, feedback) |
| `joints.py` | แปลงองศา <-> tick, ค่าคาลิเบรต |
| `motion.py` | CPG + ท่าตามโหมด + spring-damper (พอร์ตจาก `lamp.py` ฝั่งโน้ตบุ๊ก ให้ผลเหมือนกัน) |
| `safety.py` | Actuator Safety Interface + watchdog + ตรวจโหลด/อุณหภูมิ |
| `link.py` | โปรโตคอลกับโน้ตบุ๊ก (ใช้ไฟล์เดียวกันทั้งสองฝั่ง) |
| `robot.py` | ลูปหลัก ไม่แตะฮาร์ดแวร์ จึงทดสอบบนคอมได้ |
| `main.py` | ตัวที่รันบนบอร์ด (ประกอบ UART/Pin/PWM เข้ากับ `robot.py`) |
| `led.py` | ไฟโคม (PWM หรือ NeoPixel) |
| `host_bridge.py` | **รันบนโน้ตบุ๊ก** เชื่อมสมองชุดเดิมเข้ากับ serial |
| `test_fw.py` | ชุดทดสอบบนคอม ไม่ต้องมีบอร์ด (`python3 test_fw.py`) |

## ชั้นความปลอดภัย

เรียงจากที่ตัดสินใจก่อน ทุกชั้นทำงานโดยไม่ต้องพึ่งโน้ตบุ๊ก

1. **E-stop** (ถ้าต่อ `PIN_ESTOP`) -> ค้างท่า ไม่ตัดไฟ เพราะตัดไฟแล้วแขนจะตกใส่มือคน
   ส่วนการตัดไฟจริงต้องเป็นสวิตช์ฮาร์ดแวร์ที่ไม่ผ่านโปรแกรม
2. **โหลดเกิน** (มีคนจับแขนหรือมีอะไรขวาง) -> โหมด Protect ค้างท่าอย่างน้อย `PROTECT_HOLD_S`
   แล้วกลับมาเองเมื่อปล่อย มี debounce + hysteresis กันตรวจผิดจาก noise
3. **อุณหภูมิเกิน** -> ลด slew-rate เหลือ 25%
4. **โน้ตบุ๊กเงียบ** เกิน 0.5 วินาที -> ใช้ `SAFE_PARAMS` (โหมด Blind) ; เกิน 3 วินาที -> ค่อยๆ ลงท่าพัก
5. **ทุกคำสั่ง** ผ่าน clamp -> slew-rate -> (goal speed ฝั่งเซอร์โวอีกชั้น) ก่อนถึงมอเตอร์
6. **ค่ากลับหาย / NaN / แพ็กเก็ตเสีย** -> ค้างท่า ไม่ตัดไฟ และตั้ง resync ให้รอบหน้าไล่จากมุมจริง

## สิ่งที่ยังต้องตรวจกับของจริง

- **memory table ของ SCS15** ที่ใช้ (`ADDR_*` ใน `scs.py`) มาจาก SDK ของ Feetech
  แต่รุ่นย่อยต่างกันได้ `tools/scan.py` มีตัวเช็ค ถ้าไม่ตรงให้แก้ที่หัวไฟล์
- **endianness** SCS/SCSCL เป็น big-endian ส่วน STS/SMS เป็น little-endian ตั้งใน `config.py`
- **หน่วยของ goal speed** ต่างกันตามรุ่น ถ้าหุ่นขยับช้าหรือเร็วผิดปกติ ให้จูน `Joint.goal_speed()`
- **ค่า load_limit** ใน `config.py` เป็นค่าเดาล้วน ต้องวัดจริง: ใช้ `tools/calibrate.py` -> `watch()`
  แล้วลองเอามือต้านแขนเบาๆ ดูว่าโหลดขึ้นไปเท่าไร แล้วตั้งต่ำกว่านั้น
- **สายไฟ** เซอร์โวต้องแยกแหล่งจ่ายจาก ESP32 แต่ต่อกราวด์ร่วม และมีสวิตช์ตัดไฟเซอร์โวแบบฮาร์ดแวร์
- **ความเร็วลูป** บน MicroPython ช้ากว่า CPython มาก ต้องวัดด้วย `tools/bench.py` ก่อนตั้ง `FAST_HZ`

## ฝั่งโน้ตบุ๊ก

เอา `host_bridge.py` กับ `link.py` ไปวางรวมกับโค้ดชุดก่อน (`behavior.py`, `vision.py`, `viewer.py` ...)

    pip install pyserial
    python host_bridge.py --port /dev/ttyUSB0 --sim --dry-run   # ลองก่อน ไม่ต่อบอร์ด
    python host_bridge.py --port /dev/ttyUSB0                   # ใช้งานจริง

หน้าจอจะวาดมุมข้อต่อ **จริง** ที่อ่านกลับมาจากหุ่น พร้อมสถานะและ fault ของฝั่ง ESP32

## หมายเหตุเรื่องการทดสอบ

`test_fw.py` ผ่าน 16/16 บนเซอร์โวจำลองที่พูดโปรโตคอล SCS จริง ครอบคลุม: บูตตอนแขนอยู่ท่าแปลก,
แพ็กเก็ตเสีย/มาสลับลำดับ/โน้ตบุ๊กรีสตาร์ท, สายสัญญาณหาย 25%, เซอร์โวตัวหนึ่งสายหลุด,
มีคนจับแขน, อุณหภูมิเกิน, E-stop, ลูปสะดุดแล้วมีคนดันแขน
แต่ **ยังไม่เคยรันบน ESP32 จริงหรือเซอร์โวจริง** จังหวะเวลา, หน่วยของ goal speed,
และ memory table ต้องยืนยันบนบอร์ดก่อนเชื่อ
